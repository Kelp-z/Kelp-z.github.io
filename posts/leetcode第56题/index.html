合并区间：按左端点排序，逐个判断下一个区间能否继续合并。

合并区间#

给定若干个闭区间 [start, end]，把重叠的区间合并，使结果恰好覆盖原来的范围。两个区间共用一个端点也算重叠，例如 [1, 4] 和 [4, 5] 可以合并成 [1, 5]。

为什么先按左端点排序？#

在数轴上从左往右看，判断两个区间能否合并很直观。假设当前区间是 [1, 4]，下一个区间从 3 开始，两段就有重叠。从 4 开始也能接上，因此判断条件里要包含等号。

这个判断有一个前提：下一个区间的起点在当前起点的右侧，或者与它重合。输入可能先给 [8, 10]，再给 [1, 3]。直接比较会得到 1 <= 10，可这两段之间明明有空隙。先按左端点从小到大排序，就可以依次比较下一个区间的左端点 start 和 当前合并区间的右端点 right。

在 Java 的 int[][] 中，每个元素都是一个表示区间的 int[]。代码里的 Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0])) 会比较两个区间的左端点。例如比较 [2, 9] 和 [4, 5] 时，用到的是 2 和 4，所以整个 [2, 9] 排在前面。

合并时，右端点应该取谁？#

我最初在重叠时直接写了 right = end。用 [[1, 6], [2, 4], [5, 8]] 走一遍，就能看出问题。

  1. 当前区间从 [1, 6] 开始。读到 [2, 4] 时，它已经完全包含在当前区间里。如果把 right 改成 4，原来覆盖到 6 的部分就丢了。
  2. 保留右端点 6 后，再读到 [5, 8]，比较的是 5 <= 6。这次新区间伸得更远，右端点更新为 8，最终得到 [1, 8]。

两步用的是同一条规则：当 start <= right 时，保留原来的左端点，用 Math.max(right, end) 记录这一整段最远能覆盖到哪里。

如果接下来读到 [10, 12]，它的起点 10 已经超过 8。由于排过序，后面的起点至少也是 10，所以可以把 [1, 8] 放进结果，再从 [10, 12] 开始。循环结束时，手里还有最后一段，需要再加入结果一次。输入只有一个区间时，也由这一步保存它。

Java 实现#

class Solution {
    public int[][] merge(int[][] intervals) {
        List<int[]> result = new ArrayList<>();
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        int left = intervals[0][0];
        int right = intervals[0][1];
        for (int i = 1; i < intervals.length; i++) {
            int start = intervals[i][0];
            int end = intervals[i][1];

            if (start <= right) {
                right = Math.max(right, end);
            } else {
                result.add(new int[]{left, right});
                left = start;
                right = end;
            }
        }
        result.add(new int[]{left, right});
        return result.toArray(new int[result.size()][]);
    }
}

设区间数量为 n。排序耗时 O(n log n)，之后只扫描一次，总时间复杂度为 O(n log n)。排序和结果列表占用的额外空间最坏为 O(n)。
