一、这篇文章解决什么问题#

PaperLens 是一个稿件元数据核校系统：接入方提交 PDF 或 DOCX，系统在后台完成文件转换、GROBID 结构化解析、参考文献字段解析，然后在独立的浏览器窗口中让编辑核对标题、作者、摘要、关键词、参考文献、声明和统计信息。

本文记录我在 Windows 本地完成部署的全过程：

  • 启动 GROBID、DOCX 转 PDF、paper-meta 等依赖服务；
  • 启动 PaperLens 的前端和 API；
  • 打开接入方测试控制台并创建稿件任务；
  • 理解各个端口和容器的作用；
  • 遇到配置、镜像、端口和旧任务问题时知道如何处理。

本文采用“依赖服务用 Docker、PaperLens 主程序用 npm run dev”的方式。

二、PaperLens 与 paper-meta 的关系#

paperlens\        paper-metadata-9-2.zip 解压后的 PaperLens 主项目
paper_meta\       paper-meta 参考文献解析服务/模型项目

PaperLens 是主系统，负责页面、任务队列、文件处理、GROBID 调用和人工核校；paper-meta 是一个独立的参考文献字段解析器，负责从 GROBID 切出的参考文献原文中提取作者、标题、期刊、年份、卷期、页码、DOI 和文献类型等字段。

处理关系如下：

PDF/DOCX
   │
   ├─ converter：DOCX → PDF
   ├─ GROBID：PDF → TEI、正文结构、参考文献原文和坐标
   └─ paper-meta：参考文献原文 → 结构化字段

GROBID 提供参考文献在 PDF 中的坐标，paper-meta 不提供坐标；两者不能互相替代。

三、需要准备的环境#

1. Windows 软件#

  • Docker Desktop
  • Node.js 20 或更高版本
  • npm
  • 一个能正常访问 Docker Hub 的网络环境，或可用的 Docker 代理。

本次实际使用的版本是：

Node.js v22.20.0
npm 10.9.3
Docker 29.7.2
Docker Compose v5.4.0

2. 磁盘和内存#

GROBID 完整镜像约 32 GB，模型加载还会占用内存。建议预留至少 40 GB 可用磁盘空间。

四、解压 PaperLens 项目#

本次解压路径为：

E:\java\icdio\SPM\paperlens

解压后，项目根目录应该包含：

apps/
config/
converter/
docker-compose.yml
Dockerfile
package.json
python/
scripts/
tools/

五、配置 .env 和接入方凭据#

进入项目目录：

cd /d E:\java\icdio\SPM\paperlens

1. 本地开发模式的关键配置#

使用 npm run dev 时，.env 中应保持：

PORT=3100
PUBLIC_BASE_URL=http://localhost:5173
GROBID_URL=http://localhost:8070
CONVERTER_URL=http://localhost:3000
PAPER_META_URL=http://localhost:8001

PUBLIC_BASE_URL 必须填浏览器能访问的地址：

  • npm run dev：http://localhost:5173；
  • 完整 Docker Compose：http://localhost:3100。

2. 生成接入方密钥#

执行：

node scripts/api-client.mjs keygen

命令会输出 id、secret 和 encKey。把它们填入：

E:\java\icdio\SPM\paperlens\config\api-clients.json

该文件中的接入方 ID 必须和测试控制台启动时使用的 ID 完全一致。本地配置使用 local-press 时，控制台也必须使用 local-press。如果配置文件里是 local-press，却用 --id demo-press 启动，就会看到“接入方不存在或未启用”。

3 理解“接入方”配置#

PaperLens 用接入方 ID 区分调用来源，并用该接入方的 secret 和 encKey 完成签名认证、负载加密、任务归属校验和回调。

本地测试控制台使用的接入方是：

id：local-press
label：本地接入方（控制台）

它表示 PaperLens 自带的 4700 测试控制台。

SPM 后端配置的接入方是：

id：spm-local
label：本地 SPM 后端

两者可以同时存在于 config/api-clients.json，互不影响：

[
  {
    "id": "local-press",
    "label": "本地接入方（控制台）",
    "secret": "控制台密钥",
    "encKey": "控制台加密密钥",
    "webhookUrl": "http://localhost:4700/hook"
  },
  {
    "id": "spm-local",
    "label": "本地 SPM 后端",
    "secret": "SPM 专用密钥",
    "encKey": "SPM 专用加密密钥"
  }
]

启动 4700 测试控制台时，推荐读取配置文件，自动使用其中的第一个接入方：

node tools/client-console/server.mjs --api http://localhost:3100 --client-config config/api-clients.json

如果配置文件中有多个接入方，可以显式指定控制台使用哪一个：

node tools/client-console/server.mjs --api http://localhost:3100 --client-config config/api-clients.json --client local-press

SPM 后端正式调用时应使用 spm-local 对应的密钥，并按 PaperLens 接入协议生成 HMAC 签名、加密 JSON 请求，再调用：

POST http://localhost:3100/api/v1/tasks

如果控制台显示“接入方不存在或未启用”，优先检查 config/api-clients.json 中的 id 是否和启动参数完全一致。修改接入方配置后必须重启 PaperLens API；使用 npm run dev 时停止并重新启动即可。

六、需要部署的镜像和服务#

1. GROBID#

镜像：grobid/grobid:0.8.1
容器：grobid
端口：127.0.0.1:8070 → 8070
用途：PDF 结构化解析、参考文献切分和坐标提取

2. DOCX 转 PDF converter#

PaperLens 的 converter 不是直接从公共仓库拉取的最终镜像，而是根据项目里的 converter/Dockerfile 构建：

基础镜像：gotenberg/gotenberg:8.34.0-libreoffice
最终镜像：paperlens-converter:8.34.0-fonts
容器：paperlens-converter
端口：127.0.0.1:3000 → 3000
用途：DOCX、DOC、ODT 转 PDF

3. paper-meta#

镜像：paper-meta:latest
容器：paperlens-refparser
容器内端口：8000
本机开发端口：8001
用途：参考文献字段解析

这里使用本机 8001 是因为本机已有 tex2pdf 服务占用了 8000。PaperLens 容器内部通过服务名访问 http://refparser:8000，本机开发进程则通过 http://localhost:8001 访问。

4. PaperLens 主程序#

开发模式不需要单独拉取 paperlens-app 镜像：

npm run dev

它会启动 NestJS API（3100）和 Vite 前端（5173）。

七、启动依赖服务#

部署依赖镜像有两种方式：

  • 方式一：从 Docker Hub 拉取公共镜像，并在本机构建 converter；
  • 方式二：从已部署的服务器导出最终镜像，再在本机导入。

两种方式任选一种即可，不需要重复执行。网络畅通时可以使用方式一；Docker Hub 较慢、无法访问，或者希望和服务器环境完全一致时，推荐方式二。

方式一：拉取公共镜像并在本机构建#

1. 拉取并启动 GROBID#

拉取镜像：

cd /d E:\java\icdio\SPM\paperlens
docker pull grobid/grobid:0.8.1

启动：

docker compose up -d grobid

健康检查：

docker compose ps
curl http://localhost:8070/api/isalive

返回 true 或 HTTP 200 后再继续。

如果电脑没有 NVIDIA GPU，GROBID 可能因为 Compose 中的 gpus: all 启动失败。编辑 docker-compose.yml，删除或注释：

gpus: all

然后重新执行 docker compose up -d grobid。CPU 模式可以使用，只是解析速度会慢一些。

2. 拉取并构建 converter#

PaperLens 实际运行的是 paperlens-converter:8.34.0-fonts。它需要以公共 Gotenberg 镜像为基础，结合项目中的 converter/Dockerfile 和字体文件在本机构建。

先拉取基础镜像：

docker pull gotenberg/gotenberg:8.34.0-libreoffice

然后构建并启动最终 converter 镜像：

docker compose up -d --build converter

检查：

docker images paperlens-converter
docker compose ps
curl http://localhost:3000/health

如果已经成功构建出 paperlens-converter:8.34.0-fonts，以后正常启动不需要再加 --build。

3. 导入 paper-meta#

paper-meta:latest 不是 Docker Hub 上的公开镜像，不能直接执行 docker pull paper-meta:latest。需要从已有镜像的服务器导出，或者从项目提供方获取 tar 文件。

服务器导出：

docker save -o paper-meta-latest.tar paper-meta:latest

下载到本机后导入：

docker load -i paper-meta-latest.tar
docker images paper-meta

方式二：从服务器导出最终镜像并在本机导入#

这种方式直接迁移 PaperLens 真正运行的三个最终镜像：

grobid/grobid:0.8.1
paperlens-converter:8.34.0-fonts
paper-meta:latest

注意：如果已经导入最终的 paperlens-converter:8.34.0-fonts，就不需要再导出或导入 gotenberg/gotenberg:8.34.0-libreoffice。Gotenberg 只是构建 converter 时使用的基础镜像。

1. 在服务器导出镜像#

分别导出：

grobid-0.8.1.tar 
paperlens-converter-8.34.0-fonts.tar 
paper-meta-latest.tar

把 tar 文件下载到本机。

2. 在本机导入镜像#

分别导入：

docker load -i grobid-0.8.1.tar
docker load -i paperlens-converter-8.34.0-fonts.tar
docker load -i paper-meta-latest.tar

导入后确认镜像名称和标签：

docker images

应能看到：

grobid/grobid          0.8.1
paperlens-converter    8.34.0-fonts
paper-meta             latest

使用方式二时，启动命令不要加 --build，否则 Compose 可能重新构建 converter：

docker compose up -d grobid converter refparser

配置并启动 paper-meta#

无论使用哪种镜像部署方式，paper-meta 的端口配置都相同。

本机已有 tex2pdf 使用 8000 端口，因此将 paper-meta 映射到本机 8001。修改 docker-compose.yml：

refparser:
  image: paper-meta:latest
  container_name: paperlens-refparser
  restart: unless-stopped
  ports:
    - "127.0.0.1:8001:8000"

修改 .env：

PAPER_META_URL=http://localhost:8001

创建或重建容器：

docker compose up -d --force-recreate refparser

检查：

docker compose ps refparser
curl http://localhost:8001/health
curl http://localhost:8001/version

正常响应应体现 paper-meta 模型已经加载，例如 model_loaded: true，而不是 tex2pdf 的 version: 2.5.2。

最后统一启动和检查#

三个镜像准备完成后，统一启动：

cd /d E:\java\icdio\SPM\paperlens
docker compose up -d grobid converter refparser

查看状态并检查三个服务：

docker compose ps
curl http://localhost:8070/api/isalive
curl http://localhost:3000/health
curl http://localhost:8001/health
curl http://localhost:8001/version

八、启动 PaperLens 主程序#

1. 启动开发服务#

另开一个 CMD 窗口：

cd /d E:\java\icdio\SPM\paperlens
npm install
npm run dev

启动后：

前端：http://localhost:5173
API： http://localhost:3100

npm install 成功显示 added ... packages 即可。npm 的升级提示可以忽略。

打开：

http://localhost:5173/ops

这是运维面板，需要输入 .env 中的 OPS_TOKEN。它不是普通的稿件入口。

2. 启动接入方测试控制台#

PaperLens 没有普通的上传首页。稿件必须通过接入方 API 创建，因此需要启动项目自带的测试控制台：

cd /d E:\java\icdio\SPM\paperlens
node tools/client-console/server.mjs --api http://localhost:3100 --client-config config/api-clients.json

浏览器访问：

http://localhost:4700

控制台可以创建 PDF/DOCX 任务、查看状态、打开核校窗口、查看元数据、TEI、PDF 和标记结果。

九、第一次功能验证#

  1. 打开 http://localhost:4700；
  2. 在左侧填写期刊名称和稿件编号；
  3. 选择本地 PDF 或 DOCX 文件；
  4. 创建任务；
  5. 点击“刷新”，等待状态从 queued、converting、extracting、parsing 变为“已就绪”；
  6. 点击“打开核校”；
  7. 检查标题、作者、摘要、关键词、章节、声明、统计和参考文献；
  8. 在参考文献步骤检查每条引文是否被正确切分、字段是否正确着色；
  9. 保存某一步或完成最终清单。

PDF 通常不需要 converter；DOCX 会先转 PDF，再进入 GROBID 和 paper-meta 解析流程。

十、部署过程中遇到的问题与解决方法#

问题 1：pull access denied for paperlens-converter#

原因：paperlens-converter:8.34.0-fonts 是本地构建镜像，不是可以直接从 Docker Hub 拉取的公共镜像。

解决：先拉取它的公共基础镜像：

docker pull gotenberg/gotenberg:8.34.0-libreoffice
docker compose up -d --build converter

如果 Docker Hub 访问超时，检查 Docker Desktop 的代理配置，而不是执行 docker login。

问题 2：Docker 访问 auth.docker.io 超时#

典型错误：

failed to fetch oauth token

原因是 Docker 引擎的代理不可用。应确认代理软件已启动，并在 Docker Desktop 的 Settings → Resources → Proxies 配置正确的 HTTP/HTTPS 代理。配置完成后先单独测试：

docker pull gotenberg/gotenberg:8.34.0-libreoffice

成功后再运行 Compose。

问题 3：控制台提示“接入方不存在或未启用”#

原因是配置文件中的接入方 ID 和控制台启动参数不一致。

直接使用：

node tools/client-console/server.mjs --api http://localhost:3100 --client-config config/api-clients.json

问题 8：控制台列表有任务，但打开后提示“未找到该稿件”#

测试控制台自己的任务账本位于：

tools/client-console/.tasks.json

它可能保留以前创建的任务，而当前 data 目录已经没有对应的稿件文件。列表还能显示旧任务，但 API 找不到实际稿件。

处理方式：关闭 4700 控制台后，将账本改名备份：

cd /d E:\java\icdio\SPM\paperlens
ren tools\client-console\.tasks.json .tasks.old.json

然后重新启动控制台并创建新任务。

十一、端口总表#

端口 服务 说明
3000 paperlens-converter DOCX 转 PDF
3100 PaperLens API NestJS 后端
4700 接入方测试控制台 创建任务和打开核校链接
5173 PaperLens 前端 Vite 开发服务器、/ops 运维页面
8001 paper-meta 本机开发进程访问的参考文献解析服务
8070 GROBID PDF 结构化解析

十二、日常启动和停止#

开机后的启动顺序#

cd /d E:\java\icdio\SPM\paperlens
docker compose up -d grobid converter refparser

然后分别启动：

npm run dev

node tools/client-console/server.mjs --api http://localhost:3100 --client-config config/api-clients.json

停止服务#

停止 Docker 依赖服务：

docker compose stop grobid converter refparser

停止 npm run dev 或测试控制台，在对应窗口按 Ctrl + C。

查看状态和日志#

docker compose ps
docker compose logs --tail=100 grobid
docker compose logs --tail=100 converter
docker compose logs --tail=100 refparser

十三、完整 Compose 模式什么时候使用#

确认开发模式主流程正常后，再考虑：

docker compose up -d --build

完整 Compose 会同时启动 app、grobid、converter 和 refparser，更接近生产部署，但调试不方便：修改代码后需要重新构建，镜像和 GPU 问题也更容易混在一起。

因此建议：

先用 Docker 启动依赖服务
        ↓
本机 npm run dev 验证和修改
        ↓
确认流程正常后再验证完整 app 镜像

十四、清理 Docker 空间的注意事项#

镜像占用的是硬盘空间，不是持续占用运行内存。查看占用：

docker system df

确认 PaperLens 已经部署完成后，可以清理无用的悬空镜像和构建缓存：

docker image prune
docker builder prune

不要在部署尚未完成时使用：

docker system prune -a
docker image prune -a

这类命令可能删除之后还要使用的 GROBID、Gotenberg 或 paper-meta 镜像，导致再次下载。

十五、最终检查清单#

  • Docker Desktop 正常运行；
  • Node.js >= 20；
  • .env 已存在，SESSION_SECRET、OPS_TOKEN 非空；
  • config/api-clients.json 中接入方 ID、secret、encKey 已配置；
  • 测试控制台使用 local-press，SPM 后端使用独立的 spm-local；
  • grobid/grobid:0.8.1 镜像存在；
  • paperlens-converter:8.34.0-fonts 镜像存在；
  • paper-meta:latest 镜像存在；
  • GROBID 8070 健康；
  • converter 3000 健康；
  • paper-meta 8001 健康；
  • npm run dev 已启动 3100 和 5173；
  • 测试控制台已启动 4700；
  • 新建一篇稿件并成功打开核校页面。
