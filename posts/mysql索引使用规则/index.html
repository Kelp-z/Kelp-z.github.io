MySQL索引使用规则#

1. 最左前缀法则#

  • 组合索引(a, b, c)的生效顺序为：a → a,b → a,b,c
  • 不能跳过最左侧索引

2. 索引失效场景#

失效场景 示例 解决方案
字段做函数 / 运算操作 WHERE SUBSTR(name,1,3)='张' 避免字段运算，改为WHERE name LIKE '张%'
使用OR且非所有字段有索引 WHERE id=1 OR age=20（仅 id 有索引） 要么给 age 加索引，要么拆分查询
使用LIKE %xxx（模糊匹配前缀） WHERE name LIKE '%张三' 改为LIKE '张三%'（前缀匹配），或用全文索引
字段类型隐式转换 字符串字段WHERE phone=13800138000（无引号） 加引号WHERE phone='13800138000'
使用NOT IN/!=/<> WHERE age NOT IN (20,30) 尽量用范围查询替代（如WHERE age <20 OR age>30）
NULL 值判断（部分场景） WHERE age IS NULL 若字段频繁查 NULL，可加索引；或用默认值替代 NULL

3. 语法#

-- 创建索引（建表时）
CREATE TABLE user (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(20),
  age INT,
  UNIQUE KEY idx_name (name),
  INDEX idx_age (age),
  INDEX idx_name_age (name, age)
);

-- 建表后创建
CREATE INDEX idx_age ON user(age); -- 普通索引
ALTER TABLE user ADD UNIQUE KEY idx_name (name); -- 唯一索引
ALTER TABLE user ADD PRIMARY KEY (id); -- 主键索引

-- 删除索引
DROP INDEX idx_age ON user;
ALTER TABLE user DROP INDEX idx_name;
ALTER TABLE user DROP PRIMARY KEY; -- 主键索引删除

5. 慢查询日志#

--查询是否开启了慢查询日志
show variables like 'slow_query_log'

--开启慢查询日志，需要修改MySQL配置文件（/etc/my.cnf）
slow_query_log = 1(开启慢查询日志)
long_query_time(设置慢查询日志时间)

6. Profile#

#查看profile是否开启
select @@have_profiling;

#开启profiling
set profiling = 1;

#查看每一条sql耗时情况
show profiles

#查看指定query_id的sql语句各阶段耗时情况
show profiles for query query_id
